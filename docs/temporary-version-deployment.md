# Тимчасовий деплой попередньої версії без відкату main

## Принцип

Не робити commit/revert у `main` заради тимчасового тесту старого білду.
Визначити точний SHA потрібної версії, створити **окрему тестову гілку безпосередньо з цього SHA** та виконати тестовий деплой із неї. Основна гілка зберігає свої зміни.

## Перемикання на стару версію

1. Обрати SHA коміта, наприклад `153ed518d86030aad8a48c0238cf22892f2ae9ae` (класичні плашки з назвами вулиць).
2. Створити із SHA гілку, наприклад `perf/pill-labels-153ed518`. Не копіювати старі файли в `main`.
3. У тестовій гілці налаштувати `.github/workflows/deploy.yml` на `actions/checkout` **цієї гілки**, не `main`. Публікація через GitHub Pages замінює вміст **того самого сайту**, це не окремий preview URL. Використати окреме environment за необхідності.
4. Запустити **новий workflow run** (наприклад, push у тестову гілку), перевірити його результат і вміст публічного сайту. Не rerun того самого job, який уже завантажив артефакт `github-pages`: це може створити дублікати артефактів, через що `deploy-pages` завершиться помилкою.
5. Після тесту **вимкнути автоматичний push-деплой** тестової гілки (можна залишити ручний `workflow_dispatch`), щоб наступні зміни в ній не перезаписали основну версію.

## Повернення основної версії

1. Переконатися, що тестова гілка більше не запускає автоматичний деплой.
2. Запустити **новий** `Deploy site` з `main` (workflow у `main` завжди checkout-ить `main`). Це може бути `workflow_dispatch` або безпечний push документації, якщо програмний запуск недоступний.
3. Перевірити, що job `deploy` завершився **success**, та відкрити `https://truephp.lampass.top/borodianka-map/`.
4. Не видаляти тестову гілку без потреби — вона придатна для повторного порівняння.

## Важливі обмеження

- GitHub Pages тут має **один публічний сайт**. Деплой будь-якої гілки через `deploy-pages` замінює його; тестувати версії паралельно на цьому URL неможливо.
- `updating_pages` інколи зависає й завершується за таймаутом; якщо таке сталося, перевірити логи. Для нового деплою створювати **новий workflow run**, не rerun старого job із вже створеним артефактом.
- Зміни в `main` задля тестового відкату не робити.
