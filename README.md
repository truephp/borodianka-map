# Borodianka Map

Навчальний GIS-прототип на Leaflet з подвійними кольоровими лініями вулиць і будівлями Бородянки.

## Публікація
- GitHub → Settings → Pages → Source: **GitHub Actions**.
- GitHub → Actions → **Import OSM data** → **Run workflow** (гілка main). Імпортер намагається отримати валідовану межу населеного пункту (OSM relation 18281347), вулиці та контури будівель.
- Успішний імпорт створить `data/boundary.geojson`, `data/roads.geojson`, `data/buildings.geojson`. Після цього **Deploy site** запускається автоматично.
- Поки імпорт не виконався, наявний `roads.geojson` працює як раніше, а маска/будинки не показуються.

## Відображення
- Колір двох ниток уздовж доріг зараз **демонстраційний**, він не показує стан електропостачання.
- Будівлі (нейтральні) з'являються при zoom 16+; клік відкриває атрибути OSM, якщо є адреса.
- За наявності межі фон поза Бородянкою маскується. Обрізання полігонів на межі наразі приблизне: будівлі відбираються за геометричним центром, дороги — за вершинами всередині межі.
- Для продуктивності геометрію зберігаємо локально, а не запитуємо Overpass із браузера.

## Обмеження
- OSM relation 18281347 потребує підтвердження при імпорті. Якщо Nominatim або Overpass недоступні, workflow завершиться помилкою й наявні файли залишаться незмінними.
- Дорожні сегменти поки не зіставлені з будинками, дві лінії — не реальні електромережі.
- Залишилися питання коректного геометричного offset на поворотах та перехрестях.
- Не публікуємо реальних статусів ДТЕК на цьому етапі.

## Порівняння Visicom / OSM

У налаштуваннях виберіть підкладку **Visicom** та ввімкніть **Порівнювати контури OSM з підкладкою Visicom**. OSM-полігони показуються бірюзовими контурами поверх Visicom Tiles (без завантаження нової геометрії). Visicom може вимагати авторизацію через Referer або API-ключ. Ключі Data API не додавати до публічних файлів. Для Visicom Tiles потрібен ключ, обмежений за доменом, або погоджений доступ за Referer. Порівняння наразі візуальне: чисельність додаткових будинків Visicom автоматично не визначається.

## Локальна діагностика відповідностей Visicom ↔ OSM

У налаштуваннях увімкніть **Діагностика будівель**. Натисніть полігон OSM: у панелі видно його ID та адресу. Для порівняння з Visicom можна обрати локальний JSON через **Приватний JSON зіставлень Visicom**. Завантажений файл читається в пам'яті браузера: сайт не надсилає його на сервер і не зберігає в репозиторії.

Формат файлу (наведені нижче дані — лише вигаданий приклад структури):

```json
[
  {
    "osmId": 12345678,
    "candidates": [
      {"street": "Прикладна", "name": "12", "dist_meters": 5},
      {"street": "Прикладна", "name": "14", "dist_meters": 18}
    ]
  }
]
```

В інструменті показуються точні збіги адрес із OSM, кандидати для перевірки та конфлікти (та сама адреса в інших завантажених записах). Сама відстань не є підтвердженням прив'язки. Тестова GitHub Action наразі **не експортує** такого файлу — JSON потрібно підготувати локально з даних, на які є право використання. Наступний етап — погоджений захищений спосіб експорту результатів Visicom для зіставлення. Не публікуйте дані Visicom та API-ключ у репозиторії.

## Зашифрований експорт результатів Visicom

1. У `Settings → Secrets and variables → Actions` створіть окремий секрет `VISICOM_EXPORT_PASSWORD` (щонайменше 12 символів). **Не використовуйте API-ключ як пароль експорту.**
2. Запустіть workflow **Test Visicom Data API**. Він читає `VISICOM_API_KEY`, робить тестові запити, а результати шифрує AES-256-GCM з PBKDF2-SHA256 до завантаження artifact. У GitHub завантажується **лише зашифрований** файл `visicom-matches.enc.json`; строк зберігання artifact — 1 день.
3. У завершеному GitHub Actions run завантажте artifact `visicom-private-comparison` (ZIP), розпакуйте його.
4. На карті ввімкніть «Діагностика будівель», у полі «Пароль експорту» введіть `VISICOM_EXPORT_PASSWORD` та виберіть `visicom-matches.enc.json`. Файл розшифровується у вашому браузері; пароль і розшифровані дані не надсилаються на сервер.

**Увага:** artifacts публічного GitHub-репозиторію не слід вважати приватними. Шифрування обов'язкове, незалежно від терміну зберігання. Репозиторій і Pages не містять даних Visicom. Публікувати розшифрований JSON не можна без перевірки прав використання.

## Тест Visicom Feature Polygon

Workflow **Test Visicom Feature Geometry** отримує до 30 адресних features, повертає лише унікальні Polygon/MultiPolygon, шифрує у `visicom-polygons.enc.json` паролем `VISICOM_EXPORT_PASSWORD` та завантажує одноденний artifact `visicom-feature-polygons`. Файл не входить до Pages чи git. Завантажте ZIP, розпакуйте, на карті відкрийте налаштування, введіть пароль експорту та виберіть зашифрований JSON у тому самому полі імпорту. Перемикач «Показувати полігони Visicom» керує фіолетовими полігонами, popup містить адресу й Visicom ID. Це перевірка геометрії адресних features; її відповідність фізичним контурам будівель ще потрібно оцінити візуально. Ліцензія Visicom може обмежувати зберігання та повторне використання геометрії.

## Пілот просторового імпорту Visicom (незалежно від OSM)

Workflow `Test Visicom Spatial Discovery` використовує збережену межу Бородянки, шукає `adr_address` через `intersect` з WKT-прямокутником та підділяє насичені ділянки (250 об'єктів). Наразі це **обмежений пілот**: максимум чотири комірки та тридцять Feature-полігонів, не повний імпорт міста. В логах `DISCOVERY` є прапорець `complete`: лише він разом із нульовою чергою й відсутністю помилок дозволяє говорити про повноту. При успіху workflow створює лише зашифрований artifact `visicom-spatial-pilot` (1 день), файл `visicom-spatial.enc.json`. Він сумісний із локальним імпортом полігонів на карті, якщо ввести `VISICOM_EXPORT_PASSWORD`. Геометрія Visicom не комітиться та не публікується на Pages. Перевірка IoU та остаточна класифікація OSM-only/Visicom-only ще не реалізовані.
